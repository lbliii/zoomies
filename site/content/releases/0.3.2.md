## Highlights

- **Connection migration & CID retirement** (RFC 9000 §9) — detect peer address changes, validate new paths, retire connection IDs
- **Retry packet support** (RFC 9000 §8.1) — stateless address validation with Retry tokens and a pluggable `RetryTokenHandler` contract
- **Resumption exports** — `SessionTicket`, `NewSessionTicket`, and `ZeroRttPolicy` now importable from the top-level `zoomies` package

## Added

### Connection migration (RFC 9000 §9)

- Peer address change detection on incoming datagrams
- Path validation via `PATH_CHALLENGE` / `PATH_RESPONSE` before committing to the new path
- `ConnectionMigrated` event emitted once the new path is validated
- CID issuance and retirement: `NEW_CONNECTION_ID` / `RETIRE_CONNECTION_ID` frame handling, with `ConnectionIdIssued` and `ConnectionIdRetired` events surfaced to the application

### Retry packet support (RFC 9000 §8.1)

- Server-side Retry emission for stateless address validation
- Client-side Retry token handling with transparent ClientHello resend
- `RetryTokenHandler` contract for plugging in application-defined token minting and validation
- `RetryReceived` event surfaced on the client

## Fixed

- Export `SessionTicket`, `NewSessionTicket`, and `ZeroRttPolicy` from the top-level `zoomies` package — previously only accessible via submodules

## Changed

- Refactored connection packet-send helpers for clarity and reuse across Initial, Handshake, and 1-RTT spaces

## Documentation

- Fixed stale API references across the design docs
- Synced design document statuses with implementation state

## Tests

- Retry loopback integration tests (client + server, valid and invalid tokens)
- Updated connection migration and CID retirement test plans to reflect shipped behavior

## Status

- Beta: full TLS 1.3, 1-RTT, 0-RTT, loss recovery, congestion control, client + server mode, connection migration, Retry packets
- Sans-I/O design, typed, free-threading ready
