## Highlights

- **Agent-first developer UX** — a dedicated `CLAUDE.md` orientation guide covering the mental model, canonical client loop, timing contract, event cheatsheet, and top foot-guns for AI coding agents consuming Zoomies
- **Actionable error messages** — every `raise` across `core/`, `crypto/`, and `h3/` now names the offending value, the expected range or contract, and the governing RFC section
- **Three-pass hardening** — sharp-edges v1/v2/v3 tightened configuration validation, transport parameter bounds, TLS state-machine guards, H3 settings negotiation, and send-buffer accounting
- **Python 3.14+ throughout** — `match`/`case` dispatch, PEP 695 generics, and `from __future__ import annotations` removed across the codebase

## Added

### Agent & contributor docs

- `CLAUDE.md` — 60-second orientation, canonical client loop, timing contract, event cheatsheet, and top foot-guns for AI coding agents
- `AGENTS.md` — contributor conventions covering sharp-edges discipline and RFC adherence
- Expanded docstrings on every `QuicEvent` variant describing when it fires, what to do, and the relevant spec reference

### Examples

- `examples/error_handling.py` — patterns for handling every `QuicEvent` variant
- `examples/realistic_server.py` — end-to-end server loop mirroring the `CLAUDE.md` client example
- `examples/zero_rtt_resumption.py` — 0-RTT reconnect flow with ticket storage

### Actionable errors

- Raises across `core/configuration.py`, `core/connection.py`, `crypto/quic_crypto.py`, `crypto/tls.py`, and the `h3/` subpackage now carry:
  - the offending value
  - the expected range or contract
  - the governing RFC section

## Changed

### Python 3.14+ idioms

- Migrated dispatch paths in `core/connection.py`, `crypto/tls.py`, and `h3/qpack_instructions.py` to `match`/`case`
- Adopted PEP 695 generics in type-parameterized modules
- Removed every `from __future__ import annotations` import

### Sharp-edges hardening (v1 + v2 + v3)

- Configuration validation: `QuicConfiguration` now rejects contradictory combinations (e.g. `verify_mode=True` without `ca_certs`) at construction time
- Transport parameter bounds checks in `packet/transport_params.py`
- TLS state-machine guards across `crypto/tls.py` prevent out-of-order transitions
- `H3Connection` settings negotiation enforces peer and local bounds
- Send-buffer accounting (`max_send_queue_bytes`) raises `BufferError` before unbounded growth
- Connection-level validation of CID length, token length, and Retry token replay

## CI / Tooling

- **Silent-exception lint gate** — ruff rules `S110` and `S112` now fail both CI and pre-commit on `try/except: pass` and `try/except: continue`
- **`scripts/lint_raise_messages.py`** — custom linter enforcing that `raise` statements carry actionable messages, wired into CI and exercised by `tests/test_raise_messages.py`
- Tests workflow gains a dedicated lint job separate from typecheck and test stages

## Status

- Beta: full TLS 1.3, 1-RTT, 0-RTT, loss recovery, congestion control, client + server mode, connection migration, Retry packets
- Sans-I/O design, typed, free-threading ready
- Agent-ready: `CLAUDE.md` + `AGENTS.md` for AI-assisted development, actionable errors for faster iteration
